# ADR-0005：三套任务语义收敛为 Job / Attempt，但**保留**磁盘产物为准

- 状态：**已采纳**（2026-10-07 实施）
- 决策者：项目维护者
- 相关：`app/domain/jobs.py`、`app/infrastructure/jobs_repo.py`、`app/application/jobs_service.py`、`app/api/jobs.py`

## 背景

改造前项目里有**三套并存**的任务语义：

| 模块 | 语义 |
|---|---|
| `task_store.py` | SQLite 全生命周期 + 单元级进度 + 串行队列 + 崩溃回收 |
| `comfyui_job_store.py` | ComfyUI 台账（`workflow_hash` 复用、免重渲） |
| `task_lease.py` | 跨进程文件租约（`O_EXCL` + 心跳 + TTL） |

**各自都对，合起来就坏。** 一条镜头失败**算谁的**说不清——是 ComfyUI 台账没产物？
任务表 `failed`？还是租约被回收了？三个库各说各话，且没有一个是权威。

更实际的问题是「重试」这件事：它在不同模块里有不同实现，用户点一次「重跑」，
可能在报表里变成新任务，也可能变成同任务的第 N 次，历史 Attempt 全部丢失。

## 决策

收敛为**两级任务语义**（`jobs.db`）：

- **Job** = 一次**用户意图**（「渲第 3 集 ep03」）。用户点一次就是一条 Job，
  失败重试**不会**变成新 Job —— 否则「重试」和「新任务」在报表里混成一团。
- **Attempt** = 一次**执行尝试**。重试 = 同一 Job 下的新 Attempt，
  历史 Attempt 全部保留（这正是「失败为什么失败」的证据链）。

状态机由 `JOB_TRANSITIONS` / `ATTEMPT_TRANSITIONS` 收敛，非法跃迁在领域层拒绝。

### 关键设计：**收敛语义，不动既有真源**

`jobs_repo` 与 `facts.db` **分库**（`jobs.py` 模块头说明了理由），且**明确不删除**
既有的 `tasks.db` / `comfyui_jobs.json` / `task_lease.py`。`tasks.db` 是既有链路
（断点续跑 + 串行队列）的真源，本轮**不动它**。

### 必须保留的两条判据

收敛最容易犯的错误，是把「更规范的状态库」当成「更可靠的判据」而顺手替换掉。
以下两条**原样保留**，并在 `app/domain/jobs.py` 模块头显式写死：

**① 磁盘产物为准（`is_unit_done` / `resumable_units`）**
产物存在且非空即完成，**状态表丢了也能跳**。

为什么这是最值钱的：它是**唯一在状态库损坏或迁移失败时仍然成立**的判据。
改用「以 `jobs.db` 为准」看着更严谨，实则把续跑可用性绑死在一次迁移成功上——
迁移失败 = 整条生产线停摆，而且是在用户要交片的那天。

**② `workflow_hash` 免重渲复用（`comfyui_job_store`）**
Attempt 带 `workflow_hash`；哈希一致**且**产物非空 ⇒ 可免重渲复用。
`reuse_candidate()` / `reuse_hint()` 把这条判据带进新语义。

注意「且产物非空」这半个条件不能省：哈希一致但文件被删了，复用只会得到一个
指向空文件的「已完成」。

## 为什么不选另一条路

**彻底替换：以 `jobs.db` 为唯一真源，下线 `tasks.db` / `task_lease.py`。**
最干净，但要求「磁盘产物为准」退役。代价是：状态库一旦损坏，所有已完成单元都要
重渲——对一个跑 30 分钟一集、产出是 GPU 时间的项目，这是不可接受的赌博。
**收敛语义 ≠ 收敛真源。**

**保持三套并存，只加一个聚合视图。** 无成本，但「一条镜头失败算谁的」依然答不出来。
聚合视图只会把三个互相矛盾的答案并排显示，让问题更难查。

**单层 Job（不引入 Attempt）。** 少一张表、少一层。但「第 3 次重试为什么失败」就
只能翻日志——而日志正是崩掉的那个东西。

**`workflow_hash` 也一起换成 64 位满哈希。** 见下方遗留：它的 32 位截断口径未统一，
不在本轮文件范围内。

## 后果

**正面**

- 「这条镜头失败算谁的」有唯一答案：Job 状态 + Attempt 历史；
- 「重试」与「新任务」在数据层可区分；
- 崩溃后的续跑判据**没有被削弱**——这正是本决策存在的意义。

**负面 / 代价**

- 任务相关的数据现在分散在 4 处（`tasks.db` / `jobs.db` / `comfyui_jobs.json` /
  台账文件）。**本轮这是有意的代价**：先让语义清晰，再谈物理收敛。
  真要收敛，前提是先有测试护栏兜住续跑——本轮明确「只实现 + 审核，不写测试」
  （协调书 R4），不具备动它的条件。
- Job / Attempt 每次执行多写 2 行。

**遗留（不在本轮文件范围内）**

- `comfyui_job_store.workflow_hash` 历史截断到 32 位，与 ADR-0002 的
  `intent_hash` / `bound_hash`（满 64 位）口径不一致。32 位约 43 亿种可能，
  截断后可被人为构造碰撞。建议后续统一到 64 位。
