## 0. 一句话结论

**链路是通的，但通得很窄，而且「交付」这一步此前存在两个互相掩盖的静默错误。**

八个步骤的主干（`pipeline.STEP_SEQUENCE`）设计是扎实的：集级双层互斥、幂等断点续跑、
质检门禁、重试、失败隔离都在。本次审核共发现 **17 项**问题，其中 **5 项已修复**，
其余按「是否属于缺陷」分列下方。

修复后，最关键的一条断裂被打通：
**剧本要求模型逐镜产出的 3D 站位（`blocking`）此前在标准化阶段被静默丢弃**，
导致 2026-10-01 那次「治 8 镜折叠成 2 种舞台」的修复在主链路上从未生效过。

## 1. 实际链路（托管 / 自动生产）

`pipeline.run_episode()` → 8 步：

| # | 步骤 | 产出 |
|---|---|---|
| 1 | `script` | `output/scripts/<key>/epNN.json`（shots/characters/items/scenes） |
| 2 | `tts_pre` | `output/dub/<proj>/voice_bank/<角色>/ref.wav`（每角色参考音色） |
| 3 | `assets` | `output/assets/<kind>/<proj>/<名>/front.png` |
| 4 | `storyboard` | `storyboards/<proj>/epNN/shot_NN.png` |
| 5 | `keyframe` | **恒关**（`step_enabled` 直接 `return False`） |
| 6 | `video` | `videos/<proj>/epNN/scene_NN.mp4` → concat → `epNN_full.mp4` |
| 7 | `upscale` | `upscale/<proj>/epNN_upscaled.mp4` |
| 8 | `final` | `final/<proj>/epNN_final.mp4` |

**配音混音（`tts` / `mix`）不在序列内**——H3 自带原生音轨，`enable_mix` 默认 false。
这是产品决策，不是缺陷；但它意味着托管产出的成片**不经过逐镜声画对齐**。

## 2. 本次已修复（5 项）

### ✅ P0-1　`_norm_shots` 丢弃 `blocking` / `action`，3D 导演台永久回退
**文件**：`app/novel_to_script.py:1357`（新增 `_norm_blocking`）、`:2628`（接入）

剧本提示词**逐镜强制要求**模型输出 `blocking` 与 `action`
（提示词「【站位与动作（3D 导演台依赖，逐镜必填）】」），
`SHOT_FIELDS_DEFAULT` 也声明了这两个字段。但 `_norm_shots` 的字段白名单
**从未把它们拷进 row**——模型输出在标准化阶段被静默丢弃，
`te_3d_director._blocking_lookup` 恒读到 `None`、恒回退「按出场顺序排布」。

后果：`SHOT_FIELDS_DEFAULT` 注释里记录的「实测 8 个镜头折叠成 2 种舞台」这个
2026-10-01 要治的缺陷，在主链路上原样复发，且**全程无任何日志**——
看起来像是「模型不肯给站位」。

修复：新增 `_norm_blocking()`，按最终出场名单过滤（放在 `augment_cast_from_text`
之后，因为补全环节可能新增角色），x/depth/facing 走白名单并认中文同义词，
模型写了但对不上出场角色时**计数并 warning 上报**而非静默丢弃；
同时把两个字段补进提示词的 JSON schema（此前只写在补充说明里，模型常直接不输出）。

### ✅ P0-2　交付物指针指向「没烧字幕的那一版」
**文件**：`app/pipeline.py:_deliverable_of`

旧实现 `for key in ("upscale", "final")` 优先返回 `epNN_upscaled.mp4`。
但字幕是在 `step_final` 才烧进 `epNN_final.mp4` 的，而整集模式恰恰是
**拿超分片当源**再烧字幕。于是用户在「成品验收」看到、下载、发布的成片
与工作台预览的那一版**不是同一个文件**，字幕凭空消失。
（超分没丢——已被 step_final 吃进 final。）

修复：改为优先 `final`，仅在 final 缺失时才回退 upscale。

### ✅ P0-3　两套成片字幕实现写同一文件、时间轴基准还不一样
**文件**：新增 `app/subtitle_track.py`；改 `app/pipeline.py:step_final`、
`app/video_postprocess.py:finalize_episode`

`pipeline.step_final` 与 `video_postprocess.finalize_episode` 写的是**同一个**
`output/final/<proj>/epNN_final.mp4`，但：

| | 时间轴基准 | 字幕落点 |
|---|---|---|
| `pipeline.step_final` | ffprobe 实测各镜真实时长 | 正确 |
| `video_postprocess.finalize_episode` | 累加剧本 `shot["duration"]` | **随镜数累积前移** |

成片是按**真实片段**拼的，每镜实测值与声明值不等（H3 按提示词自行决定节奏，
单镜常见 0.2~1.5s 偏差），20 镜可错开 4~30 秒。两条链路谁先跑完谁说了算
（`probe_final` 见文件可播放就短路），所以表现是「同一份代码、两种字幕行为，
由历史遗留的执行顺序决定」。

`finalize_episode` 还有第二个缺陷：烧完字幕写到**旁挂** `epNN_final_subtitles.mp4`，
却 `return` **无字幕**的 `output_path`——字幕「做对了但没生效」，
而调用方（`/api/final/video`）拿这个路径去登记交付物，验收页永远是无字幕版。

修复：抽出 `subtitle_track` 作为**单一事实源**（`build_subtitle_track` /
`probe_media_duration` / `burn_subtitles_inplace`），两处共用；
并把字幕**原子替换烧回成片本体**，返回路径即带字幕的那一版。
优先级：**实测分段 > 实测总时长按占比分摊 > 剧本声明 > 默认值**。

### ✅ P0-4　混音质检 fail-open：「僵尸成功」同形态缺陷
**文件**：`app/app.py:_mix_worker`、`app/pipeline.py:probe_mix`

音频质检把「整条音轨近乎无声 / 不含音频流 / 覆盖率严重不足」判成
`blocked=True, passed=False` 之后，结论**只写进 `*_mix_report.json`**，
任务照样 `status=completed`、照样 `register_final_deliverable` 登记进验收队列。
同时 `pipeline.probe_mix` 只看 `_playable(p)`——一条「21 句里 17 句落在片外」
的成片同样判 `done=True`，托管重跑时**直接短路跳过**。

与历史「分镜僵尸成功」是同一形态：失败被记成成功。

修复：blocked 时**不登记**验收队列并把原因带进 deliverable；
`probe_mix` 改为读 `audio_qc.blocked`，为真即判未就绪、强制重跑；
`step_mix` 的失败信息带上质检原因。两处判据同源，不会「一边拦一边放」。

### ✅ P0-5　`book_outline` 读取是死代码（三处错误叠加）
**文件**：`app/app.py:1300`

```python
text, _ch = novel_parser.read_novel_text(...)   # ①
chunks = novel_parser.split_novel(text)         # ②
```

- ① app.py 顶部是 `from novel_parser import (read_novel_text, …)`——
  **按函数名直接导入**，`novel_parser` 这个模块名在本模块里并不存在 → **NameError**；
- ② `novel_parser` 里也没有 `split_novel`，真名是 `split_chapters`；
- ③ `read_novel_text` 返回 `str`，`text, _ch = …` 试图解包正文成两个变量 → **ValueError**。

三者叠在一起，还都被 `except Exception` + `logger.debug` 吞掉，
于是界面上看不到任何异常，只是「主角/反派映射一直是默认那一套」——
极难定位的静默失效。

修复：改用顶部已导入的函数名，日志级别提到 `warning`。

## 4. 前端动线与断点

用户从「导入小说」到「拿到成片」的实际路径：

1. 项目中心 → 新建项目（上传 `.txt/.docx/.pdf/.epub/.md`）→ 创建
2. 工作台 → 概览 → 逐集「文学剧本」（自动改写）
3. 逐个角色/物品/场景「生成资产」　⚠️ **无批量入口**
4. 分镜管理 → 逐镜「重新生成分镜」　⚠️ **无批量入口**
5. 分镜管理 → 「生成整集视频」
6. （可选）超分 → 「提交」
7. 声音处理 → 「生成配音」→「合成（混音）」
8. 输出与验收 → 「生成导出文件」/ 逐集「通过 / 打回」

**断点**

- ✅ **A｜托管（autopilot）已有独立 UI 入口**：`AutopilotPanel.tsx` 已接入自检、计划、启用/暂停/恢复/停止与交付进度；旧 AI 总控面板仍保留。
- ⚠️ **B｜新建项目不检查 AI 密钥 / ComfyUI 就绪**，直到剧本生成才报错。
- ✅ **C｜第 3、4 步已有批量入口**：概览页新增角色→物品→场景顺序批量生成；分镜页新增“生成本集全部分镜”首跑入口，单镜/批量返工仍保留。

- ✅ **E｜`/api/final/video` 已接入输出验收页**：按集号定位项目剧本并合成、登记交付、刷新清单；全手动链路不再依赖混音才出现成片。
