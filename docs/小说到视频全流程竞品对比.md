## 一、script（剧本生成）

**我们（当前）**：`app/novel_to_script.py`
- 分块 `build_chunks`（CHUNK_CHARS）→ `build_bible`（角色圣经）→ `build_shots_for_chunk`（逐块写镜）→ `_norm_shots`（字段白名单归一化，`:1623-1625`）。
- **已新增 P0-1 三段字段**：`first_frame / last_frame / motion`（`SHOT_FIELDS` `:169-171`，限长 40/40/30，`:1428-1430`）。
- 字段：`camera`（**复合字符串**，如「特写推入」，靠 `camera_key()` 解析景别）、`description`、`visual_detail`、`dialogue[{"speaker","text"}]`、`characters_in_shot`、`items_in_shot`、`beat`、`edit_reason`、`audio_cues`、`prompt_h3`。
- 无旁白通道（2026-09-19 产品决策，`DEPRECATED_SHOT_FIELDS` 显式拒绝 narration）。

**竞品**
- **ViMax ✅**：长文**分段压缩 + 重叠合并**（`novel_compressor.py`，chunk 65536/overlap 8192，aggregate 消重叠）；角色 `CharacterInScene` 拆 **static vs dynamic** 特征；事件/场景/角色三路独立抽取（`event_extractor` / `scene_extractor` / `character_extractor`）。
- **ArcReel ✅（新）**：`arc_script_models.py` 用 **Pydantic + 枚举归一**：`shot_type`（`:128`）与 `camera_motion`（`:148`）是**两个独立字段**，各有 `_normalize_shot_type` / `_normalize_camera_motion`（`:89-105`）——**枚举漂移会降级并打 warning，而不是静默取默认**。另有 `Dialogue`(`:114`)、`Composition`(`:123`)、`ImagePrompt`(`:133`)、`VideoPrompt`(`:142-152`)。
- **Huobao ✅**：抽取时分角色/场景/道具**三路独立跑 + 先读已有再按近名去重**（`extraction.ts`）。

**差距 / 可借鉴**
- 🔴 我们 `camera` 是**复合字符串**，景别与运镜耦合在一个字段里，必须靠 `camera_key()` / `camera_angle()` 事后解析（历史坑：解析猜错曾让质检通过率掉到 57%）。**建议拆成 `shot_type` + `camera_motion` 两个字段**（借鉴 ArcReel），并加枚举漂移降级告警。→ 这是本次最值得做的一项（P0）。
- ✅ **长文衔接已解决（P1-2 `bb4e058`）**：用 `_prev_tail_block`（`:781`）把上段结尾（摘要+末 2 条要点）注入下段 prompt（`:1013` 的 `{prev_tail}`）。⚠️ 这里有条重要教训：**ViMax 的 65536/8192 是"长文读取窗口"，与我们 CHUNK_CHARS=2400 的"LLM 调用粒度"不是一个层面，照搬数字是错的**；我们的真因是「集内相邻块接缝零上下文」，用接缝重叠解决更贴合。
- ✅ **镜头语言已内化（P1-3 `9c460ff`）**：REWRITE_RULES 第 12 条（位置朝向/聚焦部位/新场景建空间/机位克制/变化幅度自分级）——等价于 ViMax storyboard_artist 规则集的本架构落地。
- ✅ **结构漂移已审计（P2-1 `1b37531`）**：`audit_shots_structure` 扫 5 类 LLM 漂移进 events。
- 🟠 `prompt_h3` 仍是文本兼容字段；ArcReel 用 `response_schema` 让 schema 直接约束枚举（我们是事后审计，非事前约束）。

## 二、tts_pre（配音先行，锁定画面时长）

**我们（当前）**：剧本产出后先 TTS，用**每镜配音实测时长回填 `shot.duration`**（只拉长），让后续画面时长服从配音（根治「台词念不完」）。这是我们的**独特设计**，竞品未见同等实现。

**竞品**
- **ArcReel ✅（新）**：`duration_seconds: int = Field(ge=1, le=60)`（`arc_script_models.py:260/510/589/664`）——时长是**显式声明的整数字段**（1–60 秒），由模型/规划阶段给出，而非音频实测回填。
- **ArcReel ✅**：`cv.py` / `arc_character_voice.py`——角色声音绑定有两条路径：`prompt`（软约束，把 `voice_style` 写进提示词）vs `reference_audio`（挂参考音频，换跨片段**原生音色一致**），由 `derive_voice_consistency` 收口成 `voice_consistency` 单一档位供渲染层/预览/挂线共用。

**差距 / 可借鉴**
- ✅ **角色→声线绑定已落地（P2-3 `ebc58d5`）**：`_pool_gender` + `_assign_pool_speakers` 让池位**按性别组内名字排序**取第 k 位，与输入顺序解耦（治跨集音色漂移）。
- 🟠 仍未做：ArcReel `cv.py` 的 **`voice_consistency` 档位收口**（`prompt` 软约束 vs `reference_audio` 挂参考音频换原生音色一致）——我们是「是否挂参考音频」隐式，没有单一档位供渲染层/预览/挂线共用。
- 🟢 我们的「实测时长回填」比「模型声明时长」更稳（不会出现声明 8 秒但念不完），这项**我们更强**，建议保留。

## 三、assets（角色 / 物品 / 场景资产）

**我们（当前）**：角色资产多视图（`front` / `half` 等，`_pick_char_view` 按景别对档选半身/全身；`app/sheet_split.py` 从三视图整图切出单人格）。资产**已达标不重画**（改提示词须 `overwrite=true`）。性别已做 `infer_gender` / `canon_clause_text`。

**竞品**
- **ViMax ✅（最有价值）**：`character_portraits_generator.py`
  - **front / side / back 三视图**，且 **side 和 back 都以 front 图作参考图生成**（`reference_image_paths=[front_image_path]`，`:68` / `:84`）——从生成链路上保证三视图同一个人。
  - 提示词强制：**纯白背景**、**16:9 宽幅横画布**（明确写 "not a vertical portrait canvas"）、人物**居中**、**平视**、**手臂自然下垂**、**自然表情**（`:17-30`）。
  - 特征拆分直接进提示词：`features = "(static) ...; (dynamic) ..."`（`:46`）。
- **Huobao ✅**：角色特征向量强注入 + 后处理超分统一画风（📄 闭源细节）。

**差距 / 可借鉴**
- 🔴 我们是「先出三视图整图 → 再 `sheet_split` 切单人格」；ViMax 是「front 先出 → side/back 以 front 为参考生成」。**后者一致性上限更高**（side/back 天生锚定 front）。若我们的三视图是同批独立生成（非链式），可考虑改为链式。→ P0/P1（需先确认我们三视图是否独立生成）。
- 🟠 `(static)/(dynamic)` 拆分**已在 bible 源头做（P1-1 `d32fcac`，prompt-only）**，但**资产图提示词层**是否把 static/dynamic 分开写进生成提示词仍需确认（ViMax 是 `"(static) …; (dynamic) …"` 直接进定妆提示词，`:46`）。

**竞品**
- **ViMax ✅（本次最大发现）**：**机位树 camera tree**（`camera_image_generator.py:20-58` + `construct_camera_tree` `:122-181` + `_validate_camera_tree` `:256-274`）
  - 让 LLM 为每个机位找 **parent camera**：父机位画面**包含**子机位内容（中景 ⊃ 特写）；规则含「大景别优先作父」「**禁止远景直跳特写**（须逐级）」「时间邻近」「无环」「只有一个根」。

- **ViMax ✅**：`storyboard_artist.decompose_visual_description`（首帧/末帧/运动三段）——我们 P0-1 已借鉴落地。
- **ViMax ✅**：`reference_image_selector` 每帧 ≤8 张、同角色只取匹配朝向一张——我们已用 ≤8 上限 + `_pick_char_view` 对档覆盖。
- **ArcReel ✅（新）**：`sseq.py` **依赖链**：`segment_break` 断点分组（`:189-208`）+ `build_storyboard_dependency_plan`（`:211-258`）——**组内后一镜依赖前一镜**（`dependency_resource_id = previous`），组首无依赖；`resolve_previous_storyboard_path`（`:161-186`）取上一镜分镜图作输入。这就是「上一镜连续性锚点」的工程化。

**差距 / 可借鉴**
- 🔴 **我们没有「机位树 / 父子机位」概念**。我们有「上一镜连续性锚点（同场景承接时才有）」但只是**线性相邻**；ViMax 的父机位是**按景别包含关系**选的（不一定是相邻镜），并显式记录 `missing_info`。→ P0，能直接提升「同场景多镜不连戏」。
- 🟠 ArcReel 的 `segment_break` 显式断点 + 依赖链，比我们「同场景承接」的隐式判断更可控，且天然支持**部分重生成**（只重生成断点后的组）。→ P1。
