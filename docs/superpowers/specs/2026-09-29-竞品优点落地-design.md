# 设计：借鉴开源竞品优点优化漫剧生成系统

- **日期**：2026-09-29
- **状态**：设计已获用户批准（方案 A：分 4 阶段增量落地）
- **依据**：`docs/竞品对比-AI漫剧开源项目.md`（7 个项目均经 GitHub API + README 实证）
- **用户已确认**：4 类全做；预演分级**默认关**；C/D 层先做后端状态机 + API

## 1. 目标与约束

把竞品中**经实证有效、而本项目确实缺失**的能力补进来。经全量扫描 `app/` 70 个模块，确认为 8 项。

**硬约束（贯穿全部阶段）**

1. **零行为变更**：新能力默认关闭或行为等价；老项目 `config.json` 不需要迁移。
2. **可回滚**：每阶段独立收口，可单独回退。
3. **可验证**：每项配 `.workbuddy/test/verify_*.py` 离线守卫（沿用本项目既有惯例），并保证现有回归全绿。
4. **不破坏既有契约**：`shot_XX.mp4` 命名、`epNN_full.mp4`、`deliverables.json` 结构；新的 `quality_state.json` 为新增文件而非改写既有文件。

## 3. 阶段一 · 省算力

### 3.1 崩溃免重渲检查点

- **新模块** `app/comfyui_job_store.py`：任务台账，落盘 `output/comfyui_jobs.json`（原子写）。
  记录 `{prompt_id, project, episode, shot, workflow_hash, submitted_at, output_files, status}`。
- **接入点**：`comfyui_client.queue_prompt` 成功后登记；提交前（含重试与进程重启后）先查
  `GET /history/<prompt_id>`：若该 prompt 已完成且**输出文件仍存在**，直接复用，不再提交渲染。
- **安全阀**：`workflow_hash` 不匹配（工作流/提示词/参考图变了）则**不得复用**，正常重渲；
  台账条目设 TTL 与上限，避免无限增长。
- **验收**：离线守卫用假 history 响应覆盖「命中复用 / 哈希不符重渲 / 输出文件已被删则重渲」三条。

### 3.2 跨项目角色资产库 + 形象指纹复用

- **新模块** `app/asset_library.py`，库根 `output/asset_lib/characters/<sha256>/`。
- **指纹** = `sha256(规范化(提示词) + "|" + 风格 + "|" + 视图配置 + "|" + 引擎版本)`。
  **风格必须进指纹**——否则跨风格复用会直接把画风带错。
- **行为**：生成角色资产前先查库；命中→硬链（失败退回复制）到项目目录，并在产物元数据标注
  `reused_from_library=true`；未命中→正常渲染，成功后入库。
- **开关**：`asset_library_enabled`，**默认 true**（仅复用**指纹完全一致**的产物，风险可控）；
  置 false 恢复当前行为。
- **验收**：守卫覆盖「同指纹命中零渲染 / 风格不同不命中 / 库损坏不阻断生成（fail-open）」。

### 3.3 两级生产：低成本预演 → 批准 → 正式

- **新配置** `preview_before_final`，**默认 false**（用户已确认）。
- 开启后每集先出一档低成本预演（低分辨率 / 低步数 / 少帧，档位集中定义），
  预演走 4.1 的 A/B 两层；通过且获批后才排正式生产。
- **预演产物标记 `deliverable=false`，永不进导出/交付**——对齐竞品"预演不可交付"的硬规则。
- **验收**：守卫覆盖「默认关行为等价 / 开启后预演不产生可交付物 / 未批准不排正式」。

## 4. 阶段二 · 质量与可审计

### 4.1 四层质量状态机（`app/quality_stage.py`，纯函数）

- **A `technical_render`**：文件存在 + ffprobe 时长/分辨率/fps/codec/音轨。
  只描述"技术生成完成"，**不得**表述为质量通过。
- **B `content_qa`**：复用既有 `qc_client` 指标（静态率、主体运动、身份/人数/服装、OCR 随机文字、
  黑帧/花屏、前镜尾→本镜头连续性）。任一硬项失败不得标 B 通过。
- **C `editorial_review`**：人工并排复核（合同目标、参考资产、0/50/100% 帧、短预览、QA 指标）。
- **D `release_approval`**：整集联系表检查后才允许导出。

落盘 `output/qc/<项目>/<集>/quality_state.json`（**新增文件**，不改既有）。
本阶段先交付**后端状态机 + 读写 API**，前端并排审片界面留待后续。

### 4.2 哈希绑定人审晋级

- 批准记录绑定三元组 `artifact_sha256 + contract_hash + qa_report_hash`。
- **任一变化 → 批准自动失效**，回落 `pending`，并记录原因（防"批的是旧片"静默事故）。
- 接入 `pipeline._deliverable_review`；`deliverables.json` 只**增字段**，保持向后兼容读取。

## 5. 阶段三 · 稳定性

### 5.1 任务租约 + 心跳 + 超时回收

- 锁文件内容扩展为 `{pid, host, acquired_at, heartbeat_at}`；运行中定时 touch。
- 超过 TTL 判定 stale → 回收并**记 warning 留痕**（不静默抢锁）。
- 保留现有 `_acquire_episode_lock` 语义作为兼容路径。

### 5.2 结构化失败码（`app/failure_codes.py`）

- 码表：`F-SUBMIT-API / F-TIMEOUT / F-COUNT / F-QC-BLOCKED / F-REF-MISSING / F-OOM / F-DEPS` 等。
- 在 `comfyui_client` / `qc_client` / `pipeline` 抛错处分类；错误对象附 `code`，
  **原文本错误串保持兼容**（不破坏现有日志与前端展示）。

## 6. 阶段四 · 可维护

### 6.1 工作流映射外置

- `config/workflow_mapping.json` 覆盖内置 `WORKFLOW_TEMPLATE`，**缺字段回落内置默认**。
- 删除该文件即回滚到当前行为；加载失败 fail-open 并 warning。

## 7. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 复用旧检查点导致"用错产物" | `workflow_hash` 不符即禁用复用；输出文件必存在且非空 |
| 资产库跨风格污染 | 风格参与指纹；只复用指纹完全一致项；开关可关 |
| 状态机引入新单点 | 纯函数 + 只读落盘；读失败 fail-open 不阻断生产 |
| 哈希绑定误伤流程 | 只增字段、向后兼容；失效仅回落 pending 并留因 |
| 8 项交叉改动难定位 | 分 4 阶段，每阶段结束跑全量离线回归 |

## 8. 验收总口径

每个阶段结束必须：① 新增 `verify_*.py` 全绿；② 现有 `verify_*.py` 全绿；③ 前端 `tsc --noEmit` 0 错误（若动前端）；
④ 默认配置下产物与改动前**逐字节等价**（用现有测试集抽样验证）。
