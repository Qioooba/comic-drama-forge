## 一、各项目三块功能实现对照（含真实源码锚点）

### 1. 小说转剧本（novel→script）

| 项目 | 做法 | 真实源码 / 依据 |
|---|---|---|
| **ViMax** ✅ | 长篇小说**分段压缩 + 重叠合并**；先 `compress_single_novel_chunk`（chunk_size=65536/overlap=8192），再 `aggregate` 消除相邻 chunk 语义重复；规则含「丢弃非叙事文本（如'求关注'）」「保留关键对话与情绪」。角色抽取用 **Pydantic schema 强约束**：`CharacterInScene`，把特征拆成**静态（外貌/体形，不变）vs 动态（服饰/配饰/随身物，易变）**，并强制「不同角色外观要足够区分」「用可视觉化的具体描述（具体衣服颜色、大眼睛、高鼻梁），不用抽象词」。 | `HKUDS/ViMax/main/agents/novel_compressor.py`、`character_extractor.py` |
| **CineGen-AI** 📄 | **JSON Schema 强约束输出**（responseMimeType=application/json + responseSchema），杜绝模型乱说话；**逐场景分批**生成分镜避免长 JSON 截断；强制覆盖 `sceneId` 防止模型自造。 | 官方技术博客（含真实代码段） |
| **ArcReel** 📄 | **多 Sub-Agent 编排**：先「全局角色/线索抽取」→ 再「分集规划」→「剧本预处理 JSON」；**渐进式分集**：探测 → Agent 提议断点 → 用户确认 → 物理切分（人机会话）。 | `ArcReel/ArcReel` README + 工作流图 |
| **Toonflow** 📄 | **事件图谱驱动**改编 +「旁白模式 / 剧情模式」双轨；ScriptAgent 负责剧本，ProductionAgent 负责分镜/视频；支持 5 万字长文。 | `HBAI-Ltd/Toonflow-app` README |
| **Huobao Drama** ✅ | 抽取**分角色/分场景/分道具**三路独立跑，且**先读已有再按近名去重**（如「林小雨（主角）」与「林小雨」直接复用，不重复建）。 | `chatfire-AI/huobao-drama/backend/src/services/extraction.ts`（`read_existing_characters`→`save_dedup_characters`） |
| **waoowaoo / BigBanana** 📄 | 一句话→完整短剧；BigBanana 走「Script→Asset→Keyframe」工业化；waoowaoo 5 模块 Agent 流水线。 | README / 技术博客 |

**我们系统现状**：`app/novel_to_script.py` 已有 `build_chunks`（CHUNK_CHARS）+ `build_bible`（角色圣经）+ `build_shots_for_chunk` + `_norm_shots`（字段白名单、超时拆镜）。缺的是：**长文压缩合并**、**角色静态/动态特征拆分**、**近名去重**、**JSON Schema 强约束输出**。

### 2. 分镜提示词（storyboard prompts：运镜/景别/构图）

| 项目 | 做法 | 真实源码 / 依据 |
|---|---|---|
| **ViMax** ✅ | **首帧/末帧/运动三段拆解（keyframe 驱动）**：`decompose_visual_description` 把每个镜头拆成 `First Frame`（纯静态快照）、`Last Frame`（运动后的终态）、`Motion Description`（严格区分**摄影机运动** push-in/pull-out/pan/track/follow/tilt 与**画面内运动**）。镜头语言规则极细：① 指明元素在**画面中的位置**（左/右/朝向）；② 聚焦角色时写明**聚焦哪个身体部位**；③ 第一镜用**最宽景别**建立场景；④ **尽量少用机位**（运动大的才换）；⑤ 镜头内变化分 large/medium/small 三级。 | `HKUDS/ViMax/main/agents/storyboard_artist.py`、`interfaces/shot_description.py` |
| **CineGen-AI / BigBanana** 📄 | **Start Frame（必出）+ End Frame（可选）** → I2V 或首尾帧插值；锁定构图/光影，**防变形**；Wardrobe 系统（同角色多造型变体，都以 Base Look 为参考保脸一致）。 | 官方技术博客 |
| **ViMax** ✅ | 镜头数据结构 `ShotBriefDescription`：含 `cam_idx`、`visual_desc`（角色用 `<Alice>` 尖括号、对话直接写进视觉描述「<SLING> says: "..."」）、`audio_desc`（用 `[Sound Effect]`/`[Speaker]` 标记）。 | `HKUDS/ViMax/main/interfaces/shot_description.py` |
| **Huobao Drama** ✅ | 分镜与**角色/道具实体绑定**：`validateStoryboardBindings` 把 characterId/propId/sceneId 显式挂到每个 storyboard，且对重复做去重。 | `chatfire-AI/huobao-drama/backend/src/agents/tools/storyboard-tools.ts` |
| **ArcReel** 📄 | 分镜网格 + **Clue Tracking（线索追踪）**：把关键道具/场景标为「clue」，跨镜头保视觉连续；风格参考图统一注入。 | README |

**我们系统现状**：`comfyui_client.build_storyboard_prompt`（`app/comfyui_client.py:1720`）+ `h3_prompt_kit._CAMERA_EN/_CAMERA_MOVE_EN`（9 种运镜 + 景别）。已有 `CINEMATOGRAPHY_SECTION`（DOF/bokeh/SSS/发丝/布料/体积光）+ `with_tail=True` 找回质量尾。`SHOT_FIELDS_DEFAULT` 有 `camera/dialogue/audio_cues/characters_in_shot/edit_reason`。
缺的是：**首帧/末帧双帧控制**（我们是单图 I2V）、**画面内位置/身体部位聚焦**、**镜头三级变化量（large/medium/small）**、**audio_desc 结构化标记**、**道具状态（props with state）跨镜追踪**。

### 3. 台词 / 角色识别（含多角色一致性与语音绑定）

| 项目 | 做法 | 真实源码 / 依据 |
|---|---|---|
| **penshot** ✅ | **全局一致性契约（State 模型）**：`GlobalConsistencyContract` 含 `CharacterContract`（首次/末次出场、appearance_scenes 列表、**gap 检测**）、`SceneContract`（characters_in_scene、props_in_scene 带 state）。`CrossChunkValidator` 检测 `character_disappears` / `character_appears_suddenly` / `scene_jump` / `scene_too_frequent`。`ContinuityIssue` 带 severity + `auto_fixable` + `source_stage`。 | `neopen/story-shot-agent/.../continuity_guardian/{consistency_contract,cross_chunk_validator,continuity_guardian_models}.py` |
| **ViMax** ✅ | **每帧自动选 ≤8 张参考图**：`reference_image_selector` 从「角色多视图 + 前序场景图」库里，按目标帧描述挑最相关参考；一致性三维度：角色（性别/族裔/年龄/五官/发型/体形）、环境、风格；**同角色多视图只选一张（前/侧/后）匹配画面朝向**；新角色优先用肖像图。 | `HKUDS/ViMax/main/agents/reference_image_selector.py` |
| **ViMax** ✅ | **自动一致性校验**：每张生成图都用参考图核对后才进成片（`best_image_selector`）。 | 同上 |
| **Huobao Drama** 📄 | 角色**特征向量（128 维）** 强注入 SDXL cross-attention，后处理超分统一画风。 | 技术博客（闭源，描述性） |
| **waoowaoo / Toonflow** 📄 | 多角色**语音合成**、声线绑角色；Toonflow 300+ 音色库 + 跨会话记忆（ONNX 向量检索，短期/长期）。 | README |
| **我们系统现状** | `asset_prompt_kit.infer_gender/normalize_gender/canon_clause_text` 已做性别推断与注入（`性别：女`）；`continuity._locked_character_keys` 锁角色键防跨集丢；分镜 `characters_in_shot` 已绑定。 | `app/asset_prompt_kit.py`、`app/continuity.py` |

**关键差距**：我们没有 **跨镜头一致性契约（State 模型）** 与 **自动校验器**，也缺少 **每帧参考图相关性筛选（≤8 张）** 这一步——目前是「把所有角色参考图一股脑塞进 prompt」，易超参考图上限且引入噪声。

## 二、针对我们系统的优化方案（按收益/成本排序）

> 每项都给出「借鉴自谁 + 落点文件 + 具体动作」。先不写代码，确认后我再做。

### 🔴 P0 — 直接借鉴、收益最大

**P0-1. 分镜提示词引入「首帧/末帧/运动」三段结构（借鉴 ViMax / CineGen / BigBanana）**
- 落点：`app/h3_prompt_kit.py`（新增镜头拆解）+ `app/comfyui_client.build_storyboard_prompt`
- 动作：把单个 `visual_desc` 拆成 `first_frame / last_frame / motion`；`motion` 严格区分「摄影机运动（推/拉/摇/移/跟/升降）」与「画面内运动」。H3 Director 支持 I2V，可把 `last_frame` 用作尾帧约束（即使不双帧也先在提示词里声明运动终点，减少「画崩」）。
- 为什么：我们目前提示词只有单段描述，运动过程靠模型自由发挥，正是「动作连贯差」的根因之一。

**P0-2. 建立「全局一致性契约 + 跨镜头校验器」（借鉴 penshot）**
- 落点：新建 `app/continuity_contract.py`（或扩展 `continuity.py`）
- 动作：定义 `GlobalConsistencyContract`（`CharacterContract` 含首次/末次出场+gap、`SceneContract` 含 `props_in_scene` 带 state）；在 `novel_to_script._norm_shots` 之后跑 `CrossChunkValidator`，输出 `character_disappears / appears_suddenly / scene_jump` 等问题，**软告警**进现有 QC 桶（沿用 92rules 软告警口径，不硬闸）。
- 为什么：我们有 `characters_in_shot` 但无「跨镜契约」，正是人物/场景「不连戏」的系统级缺口。

**P0-3. 每帧「≤N 张相关性参考图」筛选（借鉴 ViMax reference_image_selector）**
- 落点：`app/comfyui_client._build_timeline` / `h3_director_builder`（视频参考图挂载处）
- 动作：生成每镜前，用 LLM 从「角色多视图+场景图」库里挑 ≤8 张最相关参考（同角色只取匹配画面朝向的一张），并声明「本镜哪些元素参考图 N」。
- 为什么：我们现把角色参考图全量注入，易触上限（H3 9 张上限）且引入无关噪声；ViMax 的「按帧精选」是开源界一致做法。

### 🟠 P1 — 剧本质量与可控性

**P1-1. 角色特征「静态/动态」拆分 + 近名去重（借鉴 ViMax + Huobao）**
- 落点：`app/novel_to_script.build_bible` + `app/asset_prompt_kit`
- 动作：bible 角色条目拆 `static_features`（外貌/体形，进定妆照约束）与 `dynamic_features`（服饰/配饰，进分镜约束）；抽取时先读已有角色、近名（带括号/别名）复用去重。
- 为什么：我们性别已做，但「外貌 vs 服饰」未拆，导致换装即「变脸」；近名重复建角色也是隐患。

**P1-2. 长文「分段压缩 + 重叠合并」（借鉴 ViMax novel_compressor）**
- 落点：`app/novel_to_script.build_chunks` / `convert_novel_to_script`
- 动作：超长小说先 compress（chunk 65536/overlap 8192），再 aggregate 消除相邻 chunk 语义重复，保留核心事件/对话/情绪；加「丢弃非叙事文本」规则。
- 为什么：我们目前 `CHUNK_CHARS` 直切，长文易丢主线、章节衔接硬。

**P1-3. 分镜镜头语言规则内化（借鉴 ViMax storyboard_artist 规则集）**
- 落点：`app/novel_to_script.REWRITE_RULES` + `h3_prompt_kit`
- 动作：在写剧本层加规则——① 指明元素画面内位置/朝向；② 聚焦角色时写清聚焦身体部位；③ 首镜最宽景别建场景；④ 尽量少用机位；⑤ 镜头内变化标 large/medium/small。
- 为什么：这些规则直接补「镜头语言克制」与「连续性锚点」方法论，且零 GPU 成本。

### 🟢 P2 — 锦上添花（架构级）

**P2-1. JSON Schema 强约束输出（借鉴 CineGen）**：对 `build_shots_for_chunk` 的 LLM 调用加 `response_schema`，杜绝字段漂移、强制 `sceneId` 映射。
**P2-2. 渐进式分集 + 人会确认（借鉴 ArcReel）**：长篇小说分集先探测提议断点，用户确认再切。
**P2-3. 语音-角色绑定 + 跨会话记忆（借鉴 waoowaoo/Toonflow）**：检查 `tts_client` 现状，补「角色→声线」映射与短/长记忆；我们目前有 QwenTTS 多角色，但缺显式绑定契约。
**P2-4. 道具状态跨镜追踪（props with state）**：扩展 `SceneContract.props_in_scene: name→state`，让关键道具（如「那把剑」）跨镜状态连续。

## 四、建议落地顺序

1. **先 P0-1 + P0-3**（分镜三段结构 + 每帧参考图精选）—— 直接命中「动作连贯 / 人物一致」两痛点，且都在提示词与参考图挂载层，不动主链路大模型调用结构。
2. **再 P0-2**（一致性契约）—— 系统性根治「不连戏」，软告警不阻断现有流程。
3. **后 P1 系列**（剧本侧改造）—— 风险略高，需重启 Flask 加载，建议单测 + 一次整集回归。
4. **P2 按需**。

需要我从哪一项开始写代码实现？建议从 **P0-1 + P0-3** 起步（收益最高、最安全）。
