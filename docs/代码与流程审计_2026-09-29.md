## 一、P1 问题（9 项，按建议修复顺序）

### P1-1 keyframe 模式未传 `end_frame_ref`：尾帧软锚定特性静默失效 + `<Picture N>` 声明错位
- 位置：`app/app.py:5629-5644`（refs 组装）+ `app.py:5707-5712`（提示词构建）；单镜重跑同型 `app.py:2638-2641`
- 证据：keyframe 分支 `refs = [start_p] + ([end_p] if end_p else [])`、`_c_refs = []`，
  但 `_shot_char_refs = character_refs`、`_shot_scene_refs = scene_refs`（全局默认值）未清空，
  且 `_build_h3_prompt(...)` 调用**没传 `end_frame_ref`**。于是提示词声明「`<Picture 1>` 分镜图 +
  每角色三视图 + 场景」，实际挂图只有首帧/尾帧两张。
- 影响：①「End state: the final frame must land on `<Picture K>`」尾帧锚定句在 keyframe 生产链路**永不产出**
  （h3_prompt_kit.py:795-809 的特性失效）；②声明数 >2 时 `<Picture 2..N>` 指向尾帧图或不存在槽位（静默错图）；
  链式模式下 `<Picture 1>` 标签"该镜分镜图"实际是上一镜尾帧。
- 建议：keyframe 分支传 `end_frame_ref={"name": f"shot_{sid}_end"}` 并把 `_shot_char_refs/_shot_item_refs/_shot_scene_refs`
  置空（keyframe 走专用两句式声明：`<Picture 1>` 首帧构图、`<Picture 2>` 结束帧）。

### P1-2 视频 worker 用 `except Exception` 吞掉 `cancellation.Cancelled`，取消语义被打穿
- 位置：`app/app.py:6336`（逐镜循环）+ `app.py:6354`（worker body 收口）
- 证据：`_video_generate_worker`（5464-5479）专门有 `except cancellation.Cancelled` → status=cancelled 分支，
  但 body 内两层 `except Exception` 先把 Cancelled（继承 Exception）吃掉——cancelled 分支是死代码；
  pipeline.py:288-294 特意做的「Cancelled 穿透不重试」保护被 worker 自己 defeat。
- 影响：托管暂停/停止时任务终态误报 `failed`；per_shot 模式下当前镜"失败"后循环继续，
  后续每镜仍先向 ComfyUI 提交再在等待轮询抛 Cancelled（残留远端队列任务）。
- 建议：6336 与 6354 两处 except 之前各加 `except cancellation.Cancelled: raise`。

### P1-3 托管流水线的 GPU 步骤不经 `gpu_task_gate`，与手动 GPU 任务可并发
- 位置：`app/pipeline.py:860`（storyboard）、`902`（keyframe）、`939`（video）、`1267`（upscale）——均直接 `_run_task_worker(...)` / 直接调 keyframe/upscale，无 `run_gpu_task` 包裹
- 证据：手动链路 6 处已接闸（app.py:2010/2281/2516/5224/5408/6943），托管 4 处没接；gate 的 `_running_count` 只统计手动任务。
- 影响：①托管跑整集视频期间，手动单镜重跑/超分可同时打 ComfyUI；②更隐蔽：`has_other_running_gpu_tasks()`
  在托管期间返回 False → upscale/tts 客户端发 `/free` **卸载托管任务正在用的模型**。
- 建议：在托管 4 个 GPU 步骤外层统一包 `gpu_task_gate.run_gpu_task(tid, ...)`。

### P1-4 任务态字典只增不清，24/7 挂机内存无界增长
- 位置：`app/app.py` 全文（`generation_state:193`、`dub_tasks:10689`、`mix_tasks:11695`、`upscale_tasks:6566`）
- 证据：HTTP 触发的所有任务终态后无任何 `.pop`（pipeline 内部 `pipe_*` 条目有清理，:300）。
- 影响：长期挂机内存持续增长（每条含完整 results/QC 历史）；幂等扫描与任务列表遍历随历史线性变慢。
- 建议：任务终态后按 TTL/条数上限清理，或终态只留轻量摘要。

### P1-5 Docker 镜像依赖清单不完整，构建出的容器启动即崩
- 位置：`Dockerfile:14-15` + 根 `requirements.txt`（仅 9 个包）
- 证据：Dockerfile `COPY requirements.txt` + `pip install`，CMD `python app/serve.py`；根清单缺
  `flask/flask-cors/waitress/cryptography/openai/python-dotenv`（完整版在 `app/requirements.txt:1-21`，
  桌面 CI 用的就是它）。缺 cryptography 还会让 secret_store 拒绝任何密钥落盘。
- 建议：Dockerfile 改用 `app/requirements.txt`。

### P1-6 `CORS(app)` 全开放 × `/api/ai/config/reveal` 明文回显密钥 —— 浏览器 drive-by 可偷走全部 API Key
- 位置：`app/app.py:140`（CORS(app) 即 Access-Control-Allow-Origin: *）+ `app.py:7202-7218`（reveal 端点返回明文 api_key）
- 证据：服务本身只听 127.0.0.1，但 CORS 全开让**任意网页**可在用户浏览器里跨源 fetch
  `http://127.0.0.1:5000/api/ai/config/reveal` 并读取响应——text/qc/chat 三把密钥一次全拿走；
  同理可静默调用删除项目/开启托管/改质检 base_url 等全部写接口。
- 建议：移除全局 CORS（本地前后端同源无需它），或至少把 reveal 与写接口排除在 CORS 外；reveal 加本地确认。

### P1-7 「单镜重测」从未真正重测该镜（恒发空包体）
- 位置：`frontend/src/api/client.ts:675-679` + `ProjectWorkbenchPage.tsx:1346-1360`
- 证据：`qcApi.test` 签名收 `{project?, shot_id?}` 但 body 恒为 `{}`（注释自知"传了也被忽略"，
  却仍声称后端会"按项目自动挑样张"——project 没发过去，后端回落共享 `'project'` 命名空间）。
- 影响：用户点「重测」得到的是连通性探测或共享命名空间的样张结论，与该镜无关，质检看板被误导。
- 建议：body 至少传 `{project_name, episode_no}`；后端样张挑选口径收敛到项目内。

### P1-8 截断/超时触发的二分递归丢失 `shots_hard_cap` 与 `prev_tail`
- 位置：`app/novel_to_script.py:1085-1088`（LLMTruncatedError/LLMError 二分分支），对照 :992-996 预劈半分支有传
- 影响：按章路径的单块镜头上限（78 镜 H3 资源红线）在出错二分路径失效，子块可成倍超产，
  最终靠硬截断兜底会"尾部情节缺失"；接缝上下文（P1-2 重叠注入）在该路径也静默丢失。
- 建议：补 `shots_hard_cap=shots_hard_cap, prev_tail=""` 与预劈半分支对齐。

### P1-9 局部重写更新 `camera` 但不同步 `shot_type`/`camera_motion`，重写的镜头语言被旧权威字段顶掉
- 位置：`app/continuity.py:1625-1627`（回写循环仅 `("camera","location","description","emotion","audio_cues")`）+ `:1594`（重写 prompt 也只要求 camera）
- 影响：下游取景别/运镜的权威入口优先读新字段（comfyui_client `shot_framing` 优先 `shot_type`；
  h3_prompt_kit `_camera_en(_st or camera)`），旧镜头已有非空 shot_type 时，重写模型给的新景别/运镜**完全不生效**。
- 建议：回写时 camera 变化则同步 `_norm_shot_type/_norm_camera_motion` 刷新两字段（或重写 prompt 直接要求输出新字段）。
