> 直接拿到「就位 / 缺失 / 无法判定」的逐项结果（在线走 ComfyUI `/object_info`，

> 本文档与代码**同源**——若改了映射，请同步更新 `deps_check.py` 的 `NODE_TO_PLUGIN` / `MODEL_CHECKLIST`。

## 第 1 层：ComfyUI 自定义插件（用户多半"没有"的真正卡点）

JSON 只是图，图里引用了一堆**插件节点**——没装对应插件包 ComfyUI 报"未知节点"。按链路拆分：

### 1a. 视频 · H3 Director（现役 `minimax_h3_director_二采_加速.json`，16 节点）必需

| 节点类型 | 所属插件包 | 来源 / 备注 |
|---|---|---|
| `MiniMaxH3Director` `MiniMaxH3DirectorRefine` `BasicScheduler` `ResolutionSelector` | `ComfyUI_MiniMaxH3_Director` | `github.com/AIMixer/ComfyUI_MiniMaxH3_Director`（官方 Director 插件，核心） |
| `MiniMaxH3TRTVAELoader` | `ComfyUI-H3VAE_TRT` | `github.com/lihaoyun6/ComfyUI-H3VAE_TRT`（视频 VAE 走 TRT；见 MEMORY 音频 VAE 接线红线） |
| `NvidiaDLSSFrameInterpolation` | `ComfyUI-NVIDIA-DLSS-Frame-Interpolation` | 补帧；需 NVIDIA DLSS 运行库（随包自带） |
| `PathchSageAttentionKJ` `EasyCache` | `ComfyUI-KJNodes` | SageAttention + 缓存加速 |
| `SolAttnPatch` | `ComfyUI-SolAttn_triton` | 注意：MEMORY 记录 VertiCG 崩溃真因＝SolAttn `morton=True`+3d，已定档 `morton=False` |
| `TESpeedMiniMaxH3` | `TE-Speed-MiniMaxH3` | 源码/地址需向作者确认（本机无 repo 字段） |
| 原生（无需装） | — | `UNETLoader` `CLIPLoader` `LoraLoaderModelOnly` `VAELoader` `CreateVideo` `SaveVideo` `PreviewAny`(BFSNodes 可选) `MarkdownNote`(原生) |

### 1b. 图片 · QwenImage2.1（4 个 `*_Qwen21.json`）必需

| 节点类型 | 所属插件包 | 来源 |
|---|---|---|
| `TESpeedQwenImage21` `TextEncodeQwenImage21` `QwenImage21Cache` `SaveImageAdvanced` | `TE-Speed-QwenImage21` | `github.com/tl2012tl/TE-Speed-QwenImage21`（本机为编译 `.pyd`，需 Python 版本匹配） |
| `ResolutionSelector` | （同 1a 的 Director 包提供，或由 KJNodes） | 图片模板里也引用，装 1a 即可覆盖 |
| 原生 | `UNETLoader` `KSampler` `VAELoader` `VAEDecode` `EmptyLatentImage` | ComfyUI core |

### 1c. 回退链路（仅 `MJSCXT_H3_BUILDER=legacy` 才需要，默认不用）

| 节点类型 | 所属插件包 | 备注 |
|---|---|---|
| `H3ContinuousSeamlessJoinV14` | `Herrgotts-H3-Infinite-Continuation-Suite` | 旧连续拼接母版专用 |
| `MiniMaxLowVRAMAttention` `MiniMaxChunkFeedForward` `MiniMaxH3SigmaShift` | KJNodes / minimax-h3-audio-T8 | 旧模板加速注入 |

> 结论：跑**现役**视频只需 1a + 1b 两批插件（共 **7 个包**：1a 六个 + 1b 一个 TE-Speed-QwenImage21）。legacy 回退才需 1c。
> （2026-09-29 审计修正：旧文写"6 个包"漏计了 TE-Speed-QwenImage21，与 `deps_check.NODE_TO_PLUGIN` 的 7 个 dir 不一致。）

## 新机器从零搭建 checklist（治本顺序）

```text
1) 拉项目          git clone / 解 exe；确认 workflows/ 里 6 个 JSON 都在
2) 装 ComfyUI      装好 ComfyUI（portable 或标准版），记下根目录
3) 配 COMFYUI_ROOT .env 写 COMFYUI_ROOT=<ComfyUI 根>（项目据此自动解析 models/input/output）
4) 装插件          在 ComfyUI 的 custom_nodes/ 下装 §1a + §1b 的 7 个包（或 ComfyUI Manager 装）
                    装完重启 ComfyUI，确认 16 个 Director 节点类型全部可识别（无"未知节点"）
5) 下模型          把 §2 的 H3 权重下到 ComfyUI/models/对应目录
                    ⚠️ .engine 是 TRT 编译产物，必须按你的 GPU 架构重编译（sm_120 Blackwell 注意 MEMORY 的 cudnn 红线）
6) 跑通基础链路    先跑 1 集视频（mode=episode），看 build 日志"节点 16 / 公共 0 张 / 二采 关"是否对得上
```

**最小可运行集**（不想全配）：装 1a+1b 七个插件 + 下 H3 的 6 个权重（跳过 TRT `.engine` 可先跑非 TRT 视频 VAE，画质档位降）。

## 一句话回答用户

> 模板 **JSON 已经内置**进项目（git/exe/docker 都带，开箱即有 6 个）。
> 但"能跑起来"还差两层：① 用户机器要装 **7 个 ComfyUI 插件包**（§1a 六个 + §1b 一个）；② 要下 **H3 模型权重 + 编译 TRT 引擎**（§2）。
> 这三层里，JSON 是唯一能"内置"的；插件和模型**不可能**塞进项目（体量和 GPU 架构专用性），只能给清单 + 指引。
