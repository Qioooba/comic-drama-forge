## 四、问题与不足（审计 + 本次实测）

### P1 级（本次实测直接踩到）
1. H3 提示词必须显式声明 <Picture N>，否则构建器 guard 直接抛错
   - 现象：H3DirectorBuilder.build 对「传了参考图但提示词没有 <Picture N> 声明」会 ValueError 拒绝出包（本次第一次构建触发）。
   - 说明：段提示词 <Picture N> 声明数必须与段 refs 一一对应；开公共块时 index 还被 commonEnabled 前移 K 位。最易写错又最致命的一环。

### P2 级（审计已点名的视频链路缺陷）
2. 视频 worker 用 except Exception 吞掉 cancellation.Cancelled（审计 P1-2，app.py _video_generate_worker）-> 取消语义被打穿。
3. 托管流水线 GPU 步骤不经 gpu_task_gate（审计 P1-3）-> 与手动 GPU 任务可并发，/free 会误卸载托管模型。
4. 任务态字典只增不清（审计 P1-4）-> 长期挂机内存无界增长。
5. 整集视频 run-once 同步跑占满 waitress 线程池（审计 P2-6）-> 并发即「全站卡死」。

### 本项目级观察
6. 「第一集」实际只有 3 个分镜（shot_01/03/04），不是完整一集：既有项目是简化测试产物，分镜数不齐。要完整第一集需用 LLM 从《蛊真人》开头整集生成剧本（含全部镜头）再走资产生成。
7. 九宫格分镜（SB_GRID_MODE）与单镜分镜是两套，视频工作流吃的是「单镜分镜图」：现有 storyboard 是 3x3 九宫格 9 关键帧整图，作 H3 段参考时模型拿到「9小格整图」而非单帧。应先用 /api/storyboard/grid-apply 裁成单镜图再喂 H3。
8. 3D 构图基准图 aspect 对齐隐患：基准图必须与分镜目标画幅逐像素一致；本次九宫格网格是 3:4 长条（768x1354/格 x3x3），作 <image1> 会牵引画幅。建议网格按目标画幅等比缩放后再作基准。

### 建议下一步
- 用 /api/novels/<id>/screenplay/generate + /api/script/generate 从《蛊真人》开头生成完整第一集剧本，再资产生成 -> 九宫格分镜（带3D基准）-> 裁格 -> 整集 H3 视频工作流导出。
- 视频 worker 先修审计 P1-2/P1-3/P1-4（取消穿透 + GPU 闸门 + 状态清理）。

## 七、视频提示词质量优化与质检确认（2026-10-04 用户需求）

### 7.1 回答两个问题
1. **提示词生成后是否做了质检？——是，四层流水线**（全部 fail-open，任一异常放行不阻断）：
   | 层 | 机制 | 说明 |
   |---|---|---|
   | ① 确定性检查 | `prompt_qc._check_h3` | 零模型、毫秒级：六段结构、`[Shot N]`时间码连续/递增、台词-口型动作、`<Picture N>`标签、风格声明、无台词镜的 no-voice-over 声明 |
   | ② 确定性自愈 | `prompt_qc._repair_h3` | 能修的当场修（安全追加类），修完复检 |
   | ③ LLM 提示词增强 | `prompt_enhance.enhance_prompt` | 生成前先增强，增强结果必须再过确定性检查才被采纳；篇幅骤减/骨架不符一律按原文（fail-open） |
   | ④ 质检模型语义复审 | `prompt_enhance.model_review` | 确定性通过后，再让质检模型挑语义问题；给出改进版且改进版复检分数不降才采纳 |
   - 默认模式 `repair`；**开光**：`PROMPT_ENHANCE_ENABLED`、`PROMPT_MODEL_REVIEW_ENABLED` 均默认 True（环境变量可关，文件 `prompt_enhance_config.json` 可覆写）。
   - 三种生成类型全部接预检：分镜图（`storyboard`）、资产图（`asset`/尾帧 `keyframe`）、H3 视频（`h3`）。**台词 audio 不参与**——台词会被 TTS 逐字念出，绝不能改写（有意为之）。

2. **本次实测的质检结果**（重新导出第一集，6 段全部过检）：
   - 确定性+LLM增强+模型复审：**6/6 段 accept=True，score=100，issues=0，critical=0**。
   - 质检模型确实抓到了确定性层漏检的 2 处语义问题：shot_1a「景别=特写 但起始帧写全站立姿态」、shot_1b「上下文写'画外音'但提示词声明 no voice-over」。前者是真问题（测试数据起始帧与景别不符）；后者经查是**已知假阳性**（见 7.2 ④ 修复）。

### 7.3 审计发现（未改动，属提示词链路旁的已知项）
- **长镜切段会放大总时长**：`align_frames` 把每段帧数**向上吸附**到 17k+5 网格（`n + (5 - n%17)%17`）。5s 镜头不切段 = 124 帧，切成 2×2.5s = 73+73 = 146 帧（**+17.7%**）。本次 3 镜 15s 切成 6 段后 = 438 帧 18.25s（+21.7%）。段数越多放大越多，配音时间轴会短于成片。已列 P2，建议复核 `H3_SEGMENT_MAX_SEC=4.0` 或让末段吸收余量。
